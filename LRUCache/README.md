# Version 1 – исправленный LRU - TLruCache.cpp

1. **Класс сделан шаблонным**  
   Класс теперь является шаблоном и принимает типы `Key` и `Val`.

2. **Тип метки времени изменен**  
   Для timestamp используется `uint64_t` вместо `int`, чтобы избежать переполнения, так как значение таймстемпа может превышать диапазон `int` и всегда должно быть неотрицательным.

3. **Сохранена исходная структура**  
   - `unordered_map<Key, Val> Data` хранит кэшированные данные.  
   - `unordered_map<Key, Timestamp> LastUsed` + `set<pair<Timestamp, Key>> Queue` отслеживают наименее недавно используемый элемент.  

   > Примечание: более классическое решение использует `unordered_map` для быстрого поиска по ключу и `list` для хранения позиции в очереди на удаление.  
   > В текущей реализации для вытеснения выбирается элемент с наименьшим timestamp, а `set` автоматически сортирует элементы по времени.  
   > Каждое обновление в `set` занимает `O(log N)`, в отличие от подхода `unordered_map + list`, где все операции выполняются за `O(1)`.

4. **Вспомогательная функция `ResetKeyUsage`**  
   Удаляет ключ из `LastUsed` и `Queue`, чтобы поддерживать корректное состояние LRU.

5. **Вспомогательная функция `UpdateKeyUsage`**  
   Обновляет timestamp ключа и его позицию в очереди недавно использованных элементов.

6. **Move-семантика в `Set`**  
   Значение принимается как rvalue для предотвращения лишнего копирования тяжелых объектов.

7. **Возврат указателя в `TryGet`**  
   Возвращается указатель на значение, чтобы избежать копирования тяжелых объектов.  
   Возвращает `nullptr`, если ключ не найден.  
   Для безопасного использования указателя даже при возможном rehash вызывается `Data.reserve(SizeLimit)` в конструкторе.

8. **Исключения убраны**  
   Вместо выброса исключений методы возвращают `false` или `nullptr` при неудаче, что делает API безопаснее и предсказуемее.
